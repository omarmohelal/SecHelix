# SecHelix 3.4.0-alpha.1

**Date:** 2026-09-02  
**Maturity:** public alpha  
**Public benchmark:** `NOT_MEASURED`

SecHelix 3.4 turns the V3 evidence model into a deeper evidence platform without changing the core rule: a security finding is a claim until evidence and independent verification support it.

## Highlights

### Policy-as-code

- Versioned policy packs decide what may ship and are stamped into the report they decided.
- An empty policy pack cannot silently pass a release.
- Unresolved applicability stays `INCOMPLETE` rather than being treated as a pass.
- Accepted risk requires an owner and an unexpired date.

### Independent verifier quorum

- Multiple verification paths can vote without seeing one another first.
- Outcomes distinguish `CONSENSUS_VERIFIED`, `CONSENSUS_REFUTED`, `DISAGREEMENT`, and `INSUFFICIENT_EVIDENCE`.
- A majority does not manufacture certainty when a verifier disagrees.

### Evidence intelligence

- `runtime_trace.py` correlates safe LOCAL/STAGING runtime observations with static evidence; runtime agreement alone never verifies a finding.
- `dependency_graph.py` models installed → imported → reachable → attacker-controlled → exposed instead of treating CVE presence as exploitability.
- `secret_lifecycle.py` tracks exposure through removal, revocation, rotation, cleanup, and retest; rotation without revocation is not remediation.
- `mcp_graph.py` models agent/MCP/tool/data authority and treats MCP annotations as hints rather than controls.
- `ai_inventory.py` exports an AI security inventory while keeping unknown trust boundaries `UNKNOWN` and declaration-only assets separate from observed assets.

### Remediation and campaigns

- `campaigns.py` groups verified findings by recorded root cause so teams can fix causes rather than count observations.
- `remediation.py` extends patch mode into a controlled scratch-worktree loop: existing tests, vulnerability regression, diff security review, remediation-risk checks, and independent verification must all complete before a patch is considered ready for handoff.
- A patch is still a proposal; SecHelix does not silently apply it to the caller's primary working tree.

### Proof and integrity

- Proof-bundle verification now rejects injected files that are absent from the manifest, closing an integrity gap discovered during V3.4 development.
- Evidence artifacts remain redacted by default.
- Digests are explicitly integrity checks, not origin signatures.

### Git and release hygiene

- Future public history is PR-only and squash-only.
- Squash commits use the PR title with a blank body.
- CI rejects assistant co-author trailers, session URLs, and diary-style public commit bodies after the V3.3 baseline.
- Existing public history and immutable release references are not rewritten.

### Evaluation

- `evals/ablation/` defines a controlled arm-A/arm-B experiment for measuring the incremental value of SecHelix over the same underlying model without the skill.
- The scored benchmark is still **`NOT_MEASURED`** because the sessions that authored or inspected the fixture ground truth are disqualified as evaluators.
- `evals/blind-packet/RUN.md` remains the path for a fresh, uncontaminated evaluator.

### Open-core boundary

- The local security engine remains open-source and unpaywalled.
- A future SecHelix Cloud may provide hosted history, scheduling, team workflows, organization policy, evidence storage, and enterprise controls by consuming Core artifacts rather than forking the local engine.

## Install

```bash
npx skills@latest add omarmohelal/SecHelix --skill sechelix
```

Then ask your coding agent:

```text
Use SecHelix for a complete authorized security audit of this repository.
Start STATIC, map the attack surface and trust boundaries, evaluate only applicable hypotheses,
independently verify material candidates, fix root causes, add regression proof, retest,
and produce the final release gate.
```

## Important limitations

- Alpha interfaces can still change.
- The public benchmark is not measured yet.
- The published private-owner case study is a worked example, not a general performance result.
- Trophy Case entries require attributable public evidence and permission; there are no qualifying entries yet.
