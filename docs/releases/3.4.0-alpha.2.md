# SecHelix 3.4.0-alpha.2

**Date:** 2026-09-02  
**Maturity:** public alpha  
**Blind label evaluation:** `MEASURED`  
**Full SecHelix workflow:** `NOT_MEASURED`

No new engine capability ships in this release. It exists to make the public record match what has
actually been measured, and to make the project findable by what it *is* rather than only by its
name.

## The measurement boundary, stated once and repeated everywhere

The blind evaluation packet finally has an uncontaminated run. On 2026-09-02, 76 cases were judged by
76 independent processes, each launched from an empty directory containing only the case file. None
cloned the repository, and none saw a label, a rationale, a pairing, or how many cases were
vulnerable.

| Metric | Value |
|---|---|
| Precision | **0.950** |
| Detection recall | **1.000** |
| False-positive rate | **0.053** |
| False-positive rejection rate | **0.947** |
| Counts | **TP 38 · FP 2 · TN 36 · FN 0** |

Committed as [`evals/results/claude-sonnet-5-blind-2026-09-02.json`](../../evals/results/claude-sonnet-5-blind-2026-09-02.json).

**This is a label-only synthetic evaluation, not measured performance of the complete SecHelix
workflow.** The protocol asks one question per file and takes one label back. It did not run
attack-surface mapping, the independent refutation pass, the evidence adapters, evidence-chain
construction, remediation, regression proof, or the release gate.

So:

- **Blind label run — `MEASURED`.**
- **Full workflow — `NOT_MEASURED`.** `applicability_accuracy`, `regression_proof_rate` and
  `release_gate_accuracy` keep the literal string. `verified_precision` is `0.0` only because
  `verification_status` was `NOT_RUN` for every case.

Do not read `0.950` as "SecHelix accuracy". One model, one run, on a balanced 38-pair authored suite
that is mostly single-file and mostly Python. Every limitation is recorded in the result file, not
only in the write-up.

### A defect the run exposed in the protocol itself

`evals/blind-packet/RUN.md` published the expected packet digest as `c15861ed…`, which had been
computed on a **Windows working copy with CRLF line endings**. Anyone following the documented `curl`
download — on any platform — gets `1ad970d1…` and would conclude the suite had changed. The content is
byte-identical apart from 613 carriage returns. Both digests are now documented, with the canonical
LF value as the expected one.

## Explicit Google-Extended policy

`robots.txt` now names `Google-Extended` alongside `OAI-SearchBot` and `PerplexityBot`, with the same
public-allow / admin-deny shape, and six automated assertions cover it.

`Google-Extended` controls whether content Google has already crawled may be used for future Gemini
model training and for grounding in Gemini Apps and Vertex AI Grounding with Google Search. **It is
not a Google Search ranking signal**, it does not affect indexing, and allowing it does not make any
assistant cite this site. It is a permission, not a promise.

## Entity consistency

The homepage structured-data graph now uses stable `@id` values (`#publisher`, `#software`,
`#website`) so the Organization, SoftwareApplication, SoftwareSourceCode and WebSite nodes reference
one another instead of floating as four unrelated objects. `applicationCategory` is
`DeveloperApplication`, the repository relationship is explicit, and `/about` opens by naming the
project, its author, its licence, its repository and its official site.

There is still **no** `aggregateRating`, `reviewRating` or `ratingValue` anywhere, and `sameAs`
carries only live accepted listings — no pending pull requests, no search results, no invented
profiles.

## No capability inflation

Nothing in this release claims that any assistant will recommend SecHelix, that discovery work
improves security performance, or that the measured label number describes the workflow. Search and
directory visibility continue to be measured separately from implementation, and recorded honestly
whether or not the result is flattering.
