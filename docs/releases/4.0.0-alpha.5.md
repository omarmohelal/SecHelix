# SecHelix 4.0.0-alpha.5

**Date:** 2026-09-13

**Maturity:** public alpha

**Optional Python runner:** 0.3.0, unchanged

## SEO and safe cleanup workflows

SecHelix now routes requested quality reviews to two self-contained references:

- SEO Audit covers all 20 requested checks: noindex, titles, descriptions, alt text, Core Web Vitals, sitemap, Open Graph image, broken links, headings, backlink strategy, slugs, internal links, canonical, HTTPS, image compression, schema, Search Console, one primary h1, robots.txt and mobile responsiveness.
- Codebase Cleanup covers dead code, duplicate logic, unused UI, complex implementations, legacy code, redundant queries/API calls, disconnected files and technical debt. Every issue requires evidence, value analysis, estimated impact, deletion risks and a verification/rollback plan.

The command cookbook includes audit-only recipes and a combined audit/fix/verify prompt. The canonical Skill and discovery adapters route to these workflows; references are included in the portable distribution.

## Boundaries

Intentional noindex is preserved. Unused-code tool output does not establish non-use: dynamic discovery, external consumers and operational contracts require investigation. No destructive database cleanup, automatic outreach or invented Search Console verification. Lab measurements are distinguished from field Core Web Vitals.

These are agent-guided instructions, not new CLI subcommands or autonomous scanners. The security catalog, finding schemas, gates, runtime behavior and runner version are unchanged. Quality reports cannot confer a security PASS. No new end-to-end effectiveness or ranking improvement is claimed.

The normal repository validation and release workflow apply. Release artifacts are generated by the existing version-release workflow after merge.
