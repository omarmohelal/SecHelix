# SecHelix 4.0.0-alpha.6

**Date:** 2026-09-15

**Maturity:** public alpha

**Optional Python runner:** 0.3.0, unchanged

## A curated edition for skill directories

GitHub's awesome-copilot declined the full skill as a directory entry
([github/awesome-copilot#2899](https://github.com/github/awesome-copilot/issues/2899)): its
`SKILL.md` sat just under the 500-line guideline, the skill directory carried many supporting
files, and the submission read as project promotion. That feedback is accurate for a directory
whose entries are single-purpose skills.

This release keeps the full framework and adds a separate, small package for that audience:
`distributions/awesome-copilot/`, with one skill, `sechelix-lite`.

| | Full skill (`skills/sechelix`) | Curated edition (`sechelix-lite`) |
|---|---|---|
| `SKILL.md` | 433 lines | 197 lines |
| Supporting files | 159 | 5 Markdown references |
| Runtime, catalog, schemas, adapters | included | not included |
| SEO and cleanup workflows | included (on request) | not included |

The curated edition covers scope and authorization, attack-surface mapping, applicability,
six review lanes (surface, auth and authorization, web inputs, business logic and races, supply
chain and AI agent boundaries, independent verifier), root-cause fixes, regression proof and the
`PASS` / `PASS_WITH_KNOWN_RISK` / `BLOCKED` / `INCOMPLETE` verdict. It is named `sechelix-lite`
because `gh skill install` discovers nested skills and would otherwise resolve `sechelix` to it.

`scripts/validate_distribution.py` runs in CI and keeps the edition within its budgets
(220 lines, 6 supporting files, 64 KB), inside Agent Plugins v1.0.0, at the release version, free
of runtime references and product or SEO copy, and aligned with the status and verdict
vocabularies in `schemas/`. Before release it passed awesome-copilot's own intake tooling run
locally (`vally lint`, spec compliance, version match) and a cold install with Copilot CLI 1.0.83.

## Leaner full skill

- `SKILL.md` moves runtime-only resource lists, helper modules and commands to
  `references/runtime.md`, which is loaded only when the runtime is present: 483 to 433 lines,
  22.9 KB to 19.3 KB of always-loaded context. No methodology rule changed.
- The portable bundle stopped shipping files no review step reads: a stale `agents/README.md` that
  moved to the docs in 3.2, the deliberately vulnerable `examples/demo-app`, and rendered report
  samples. `sync_portable_skill.py` now prunes files no canonical source produces.
- A stale "fifteen JSON Schema" statement (22 exist) is corrected, and the documentation count
  check now covers the authored portable `SKILL.md`.

## Boundaries

No security semantics, catalog entries, schemas, gates or runtime behavior changed. The curated
edition is a rendering of the canonical workflow, not a separate methodology. No detection or
comparative performance claim is made; full-workflow metrics remain `NOT_MEASURED`.
