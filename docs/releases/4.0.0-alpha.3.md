A manifest-correctness release, cut the same day as `4.0.0-alpha.2` because the
artifact under review should be the correct one.

## Agent Plugins v1.0.0 compliance

GitHub's `awesome-copilot` intake validated the `4.0.0-alpha.2` submission and
returned a non-blocking spec warning:

```text
Agent Plugins v1.0.0 manifest warnings:
- top-level field "skills" is not part of Agent Plugins v1.0.0
- top-level field "agents" is not part of Agent Plugins v1.0.0
- schema validation: manifest must NOT have additional properties
```

They were right. The published schema sets `additionalProperties: false`, and
skill and agent discovery in v1.0.0 is by directory convention rather than by
declaration — so `"skills": "./skills/"` and `"agents": "./agents/"` pointed at
the two directories discovery already finds, bought nothing, and failed schema
validation. Both are removed.

Two tests replace them. One asserts the manifest carries no top-level key
outside the v1.0.0 set, so a future addition fails locally rather than in
someone else's review queue. The other asserts the conventional directories are
actually there — removing a pointer is only safe while the convention it pointed
at holds.

Nothing about installation changes. The intake's install smoke test, vally lint,
version match and ref/SHA consistency gates all passed at `4.0.0-alpha.2`; this
clears the one warning alongside them.
