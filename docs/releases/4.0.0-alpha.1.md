# SecHelix 4.0.0-alpha.1

**Date:** 2026-09-03  
**Maturity:** public alpha  
**Portable Agent Skill:** still works without the optional runtime  
**Optional Python runner:** `0.1.0`  
**Blind label evaluation:** `MEASURED`  
**Full SecHelix workflow:** `NOT_MEASURED`

SecHelix V4 turns the evidence-first methodology into an optional executable security runtime while preserving the same rule the project started with: **a candidate is not a vulnerability until the evidence chain earns that claim**.

The portable `skills/sechelix/` bundle remains the product entry point and does not require the runner. The new `sechelix` Python runtime is an optional orchestration layer for teams that want deterministic DAG execution, budgets, replayable evidence, coverage state, local APIs and MCP integration.

## Optional evidence runtime

V4 ships a standard-library-only runner with:

- a deterministic reasoner DAG with dependency-aware blocking rather than silent skipping;
- least-context views so specialists receive only the slices they need;
- token/cost/time budget accounting with reservations that close double-admission races;
- durable coverage ledgers that distinguish observed, examined, stale and blind surfaces;
- replayable run workspaces with integrity checks and revision identity;
- Markdown, JSON, SARIF and standalone HTML output;
- loopback API and MCP surfaces that do not expose an arbitrary shell;
- provider isolation with a Claude Code adapter and fail-closed structured-output validation;
- adaptive scheduling that can deepen a lane or queue variant work without treating a heuristic as evidence.

The runner owns no second definition of findings or verification. It consumes the same versioned SecHelix contracts used by the portable skill.

## Threat modeling and false-positive discipline

The runtime now builds threat candidates from the recorded attack-surface graph rather than from free-floating STRIDE labels. An adversarial threat-model pass can support, refute or leave a candidate unresolved, but supported threats require evidence.

False-positive learning is deliberately conservative. Repeated cross-target refutations may produce a **verification question** for future reviews; they cannot create a rule that auto-dismisses a finding. Single-target history and secret-shaped material are rejected from that guidance path.

## Bounded LOCAL proof execution

Proof plans can now execute in `LOCAL` mode for five deterministic classes:

- two-identity authorization / IDOR controls;
- path traversal against a fixture sentinel without persisting the response body;
- bounded race/idempotency requests with explicit state readback;
- webhook signature, invalid-signature and replay controls;
- SSRF using a loopback-only callback listener — never a public OOB service.

XSS remains `BLOCKED` unless an explicit browser backend is supplied. No browser dependency is silently installed.

A security review of the proof transport itself found an authority gap: a policy-approved URL could have been followed through ambient HTTP behavior. V4 closes that class of bypass by connecting only to literal loopback addresses (`127.0.0.1` or `::1`) for LOCAL HTTP proofs, rejecting DNS names and URL user-info, using no ambient proxy, and following no automatic redirect. CodeQL, dependency review and the complete validation suite passed after the hardening.

Proof execution still does **not** promote a finding. Results are `VULNERABLE_BEHAVIOR`, `SECURE_BEHAVIOR`, `INCONCLUSIVE` or `BLOCKED`; independent verification still has to establish attacker control, reachability and the failed security boundary.

## Protocol and native lanes

V4 adds applicability-gated protocol packs for deeper review of:

- GraphQL;
- WebSocket;
- gRPC;
- OAuth / OIDC;
- SAML;
- JWT;
- webhooks and callback trust;
- HTTP desynchronization, cache and proxy boundaries.

It also adds a native-source lane for C, C++ and Rust. Unsafe/FFI/parser/crypto patterns remain **candidate signals**, not automatic vulnerability claims.

## Deterministic scanner interoperability

Opengrep joins the scanner adapters alongside Semgrep, CodeQL/SARIF, OSV, Gitleaks, Trivy, package audits, Playwright, ZAP and safe Nuclei ingestion. Scanner output remains untrusted candidate evidence and never assigns a SecHelix verdict by itself.

## Workbench V4

The production site now has a local-first V4 run explorer at `https://sechelix.com/workbench/v4`.

A user can select a local `run.json` plus optional `graph.json` and `coverage.json`. Parsing stays in the browser; the artifacts are not uploaded. The viewer shows the recorded DAG, blocked/failed nodes, mandatory evidence state, measured model/cost/token/time telemetry, routing reasons, budget refusals, least-context views and coverage blind spots. It does not recompute verdicts or replay models.

## Arena: full-workflow measurement without a fake leaderboard

`evals/arena.py` adds the missing protocol for measuring workflow properties that vulnerable/clean labels cannot answer:

- applicability accuracy;
- independent-verification accuracy;
- false-positive-refutation accuracy;
- root-cause accuracy;
- regression-proof accuracy;
- release-gate accuracy.

Arena does not install or run SecHelix or competitors. It records evidence from isolated authorized runs. A record stays `NOT_MEASURED` unless the participant version is pinned, capability scope is explicit, every opaque blind case is assessed exactly once, packet/prediction/truth digests are present, the evaluator is independent, and contamination is explicitly ruled out.

Comparisons are allowed only when both records are measured against the same blind packet and have the same participant category and capability scope. A narrow SAST engine is not ranked against a broad remediation workflow as though they perform the same job.

Templates exist for SecHelix, OWASP AppSec Agent, OWASP Secure Agent Playbook, Vulnhuntr and Opengrep. External capabilities are placeholders until verified against the exact tested version. **No competitor result is published by this release.**

## Measurement boundary

The existing uncontaminated 76-case blind-label evaluation remains the only public measured model result:

| Metric | Value |
|---|---:|
| Precision | **0.950** |
| Detection recall | **1.000** |
| False-positive rate | **0.053** |
| False-positive rejection rate | **0.947** |
| Counts | **TP 38 · FP 2 · TN 36 · FN 0** |

That run is a synthetic label evaluation, not a measurement of the V4 workflow. The end-to-end runtime — applicability, independent verifier, remediation/regression and release gate — remains **`NOT_MEASURED`** until an uncontaminated full-workflow run exists. V4 adds the machinery to measure it; it does not invent the result.

## Distribution and remaining external blockers

The Agent Skill remains installable through the existing skills ecosystem. The optional runner package is buildable and has no runtime dependencies, but PyPI upload remains a separate external step because this project session does not hold a PyPI publishing credential.

A public Trophy Case entry also still requires an attributable authorized result on a public project or explicit maintainer permission. Public availability of a repository is not treated as permission for active testing.

V4 is therefore a capability release, not a claim that SecHelix is now the most accurate AppSec agent. The next credibility milestone is external end-to-end evidence produced under the Arena protocol.
