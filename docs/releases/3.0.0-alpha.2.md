# SecHelix 3.0.0-alpha.2

Alpha.2 opens SecHelix to community extensions without turning the registry into
an automatic code-execution or trust channel.

## What changed

- Community extension types: adapter, catalog pack, eval pack, policy pack,
  reporter, specialist, and integration.
- Versioned `extension-manifest-v1` and `extension-registry-v1` contracts.
- Explicit network, filesystem, subprocess, secret, data-handling, safe-default,
  fixture, and evidence-output declarations.
- A curated lifecycle: `COMMUNITY` → `INCUBATING` → `OFFICIAL` (or `DEPRECATED`).
- CI validation, deterministic contract tests, starter manifest, issue form, and
  contributor guide.
- A redesigned private product preview with an interactive evidence workbench,
  command palette, extension forge, and dedicated contribution route.

## Trust boundary

A registry entry does not execute or install extension code. New manifests are
structurally limited to `COMMUNITY`, non-destructive defaults, and no production
mutation. Promotion requires a separate maintainer review record with fixture
proof.

- Skill surfaces, local links, install snippets, secrets, and public/private source
