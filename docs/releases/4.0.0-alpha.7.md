# SecHelix 4.0.0-alpha.7

**Date:** 2026-09-21

**Maturity:** public alpha

**Optional Python runner:** 0.3.0, unchanged

## The installed skill no longer ships code

`npx skills add omarmohelal/SecHelix --skill sechelix` used to install 52 Python files:
`sechelix_core`, the scanner adapters, the report renderer and six scripts. Nothing in a review
executes them. They were weight on every machine, and they were executable surface that every
install-time security audit has to judge.

| | Before | After |
|---|---|---|
| Files | 160 | 102 |
| Size | 2.0 MB | 1.46 MB |
| Executable files | 52 | 0 |

What ships is what the workflow reads: `SKILL.md`, the references, the 17 specialist profiles,
the 546-hypothesis catalog, the 22 JSON Schema contracts, the Gold Check Packs, the knowledge
registry and graph, the policy examples, and the scope and report examples.

## The helpers did not go away

They are distributed where they can actually be installed:

- `python -m pip install sechelix` installs the `sechelix` CLI and makes the `sechelix_core`
  helpers that `SKILL.md` names importable — `untrusted_repo`, `attack_chains`, `variant_rules`,
  `patch_mode`, `diff_review`, `revision`. `pipx` and `uv tool` install the command but keep the
  modules in their own environment.
- A repository clone adds the release-gate script, the report renderer, the scanner adapters and
  the validators, which are not in the wheel.

`references/runtime.md` states which source provides what, and `SKILL.md` states that the
workflow requires neither: every phase is executable by hand against the contracts in `schemas/`.

**If you ran `python scripts/security_gate.py` from inside an installed skill, that path is
gone.** Use a repository clone, or `sechelix report` from the installed package.

## Gates

`scripts/validate_skill.py` now fails when any file with an executable suffix appears in the
bundle, and a regression test asserts the same. `tests/test_repository_checks.py` also asserts
the instructions still reach their optional helpers, so removing the code cannot silently orphan
the calls that depend on it.

## Boundaries

No security semantics, catalog entries, schemas, gates or runtime behaviour changed. The
methodology is identical; only what the package carries changed. The curated `sechelix-lite`
edition is untouched, and the runner stays at 0.3.0 with no PyPI release.
